# Repo Reality

This repo is not a blank slate.

## What is already materially real

- Local-first workflow engine.
- Sandbox / review / apply patterns.
- Governance / trust / approvals / audit layers.
- Continuity / migration / stable-v1 layers.
- Investor demo CLI flow.
- Demo bootstrap / readiness / env-report.
- Demo onboarding start/reset.
- Demo onboarding user-preset.
- Demo onboarding bootstrap-memory.
- Demo onboarding ready-state.
- Workspace home.
- Day status.
- Guidance next-action.
- Guidance operator-summary.
- Inbox list.
- Investor-demo rehearsal and hardening work.
- Browser-based investor desktop shell direction exists and may already be partially implemented.

## What is likely partial

- Desktop UI may not be fully unified with backend truth.
- Some surfaces may still be mocked, cached, or fallback-driven.
- Some guidance and first-value flows are still too backend/internal-feeling.
- Mission-control and expensive state aggregation may still rely on bounded timeout behavior.
- Deployment, packaging, and meeting-readiness may be incomplete.

## What must not be rebuilt from scratch

- Core local-first product semantics.
- Approval-gated safety model.
- Existing CLI product surfaces unless a concrete integration issue requires refinement.
- Existing data shapes unless absolutely necessary and carefully migrated.

## Strategic reality

The project is now at an integration and realization stage, not a greenfield invention stage.
The next work must reduce drift, unify abstractions, and make the system more real and more usable.
