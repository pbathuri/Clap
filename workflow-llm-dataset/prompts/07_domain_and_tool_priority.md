# Domain and Tool Priority

## Priority domains

- Analytics / spreadsheets / dashboards
- Design
- Coding / engineering

## Tool priority stance

The architecture should support discovery of the tools the user actually uses frequently.
Tool priority should be learned from:

- onboarding
- folder analysis
- app usage inference where allowed
- workflow-tree patterns
- repeated task observation

## Explicit first-class tool families

- Finder
- Terminal
- Browser
- Excel
- Google Sheets / CSV workflows
- Tableau
- PowerPoint / Keynote
- VS Code / Cursor
- Figma
- Adobe Illustrator
- Adobe Photoshop
- Notion / notes apps
- SQL clients
- Python notebooks

## Design stance

All of design matters later.
First build the substrate:

- asset understanding
- project structure understanding
- role inference
- tool policy boundaries
- action proposal
- supervised execution model

## Domain strategy

Do not hardcode the product as only one profession.
Use the workflow-tree substrate so the same architecture can support multiple roles with different tool mixes and policies.
